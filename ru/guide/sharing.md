# Шаринг и организации

Делитесь отдельными элементами или работайте в **организациях** с другими пользователями OpenKey на **одном self-hosted сервере**. Всё, что сервер хранит для орг и шаров, остаётся **шифротекстом** — клиенты оборачивают ключи для получателей; API никогда не расшифровывает имена или полезную нагрузку.

<img src="/guide/sharing-key-wrap.svg" alt="Sharing model: publish identity keys, wrap org keys for live shared collections, or wrap entry shares as frozen ciphertext snapshots; server stores opaque blobs only" class="ok-diagram" width="920" height="400" />

**Требуется OpenKey Pro** и настроенный аккаунт [сервера](./server) (регистрация / login + sync). Опубликуйте ключи идентичности до приглашений или шаринга, чтобы пиры могли обернуть ключи для вас.

## Предварительные условия

1. Установите приложение ([Загрузка](./download)) и разблокируйте сейф.
2. Подключите **Настройки → Данные → Self-hosted сервер** и синхронизируйте.
3. **Настройки → Данные → Опубликовать ключи идентичности** (Pro) — загружает непрозрачный публичный / обёрнутый приватный ключевой материал для шаринга.
4. Получатели должны использовать **тот же URL сервера** и опубликовать ключи идентичности (или хотя бы зарегистрированный аккаунт, который сервер может найти).

## Организации

Путь: **Настройки → Данные → Организации**, или **Хаб элементов → Организации**.

### Создать орг

1. Откройте Организации → создать.
2. Клиент шифрует имя орг и оборачивает ключ орг для вас как владельца.
3. Создайте **общие коллекции** в орг для командных логинов (зашифрованные имена + полезная нагрузка).

Общие записи орг живут в этих коллекциях и синхронизируются как непрозрачные строки (`encrypted_payload`).

### Пригласить участников

1. Откройте орг → **Пригласить участника**.
2. Введите их **email** (должен уже существовать на этом сервере) и выберите роль (`admin` / `member`).
3. Клиент оборачивает ключ орг для их публичного ключа идентичности и публикует приглашение.
4. Они видят **Ожидающие приглашения**, принимают и затем могут открыть общие коллекции после sync.

Владелец/admin может отозвать ожидающие приглашения, менять роли или удалять участников. Владелец не может покинуть орг; передача владения — не отдельный путь восстановления — планируйте админов осторожно.

### Принять приглашение

1. Откройте Организации → **Ожидающие приглашения**.
2. Примите. Синхронизируйте, чтобы появились общие коллекции.
3. Используйте тот же мастер-пароль и сервер, что обычно — вступление не даёт серверу plaintext.

## Шары элементов и коллекций

Поделитесь одним логином (или коллекцией) с другим пользователем без добавления в орг.

1. Откройте запись (или коллекцию) → **Поделиться**.
2. Выберите email получателя на вашем сервере.
3. Клиент оборачивает ключ элемента для них. **Шары записи делают снимок** зашифрованной полезной нагрузки на момент шаринга.
4. Получатель: примите в UI шаров / ожидающих; снимок импортируется в **их** сейф (новый локальный uuid).

### Семантика снимка (важно)

- Принятие шара **записи** копирует замороженный шифротекст в личный сейф получателя.
- Последующие правки исходной записи владельца **не** отправляются получателям.
- **Отозвать** останавливает ожидающее принятие; **не** удаляет уже импортированную копию на устройстве получателя.

Относитесь к шарам как к передаче запечатанной копии, а не живого общего документа. Предпочитайте **общие коллекции орг**, когда нужен постоянный командный доступ к одному шифротексту под общим ключом орг.

## Расширение

В автономном (серверном) режиме [расширение браузера](./extension) может перечислять/принимать/отзывать шары и перечислять организации / общие коллекции. Режим десктопного моста полагается на разблокированное приложение для операций сейфа.

## Заметки по безопасности

- Делитесь только с людьми и устройствами, которым доверяете — принявшие могут расшифровать то, что вы обернули для них.
- Имена орг, полезная нагрузка шаров и blobs ключей идентичности непрозрачны на сервере ([Безопасность](./security)).
- Отзыв доступа на сервере не стирает локальные копии, уже расшифрованные на другом устройстве.
- Держите Pro-бэкапы; шаринг не заменяет офлайн-материалы восстановления.
