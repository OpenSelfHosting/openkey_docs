# Nearby LAN-синхронизация

**OpenKey Pro** может синхронизировать один сейф между устройствами в локальной Wi‑Fi **без self-hosted сервера**. Шифротекст передаётся по спаренной LAN-сессии; ключ сейфа делится только после явного нажатия **Связать сейф**. На **новом устройстве** можно также **скопировать** существующий сейф через Nearby при первом запуске (клонирование сейфа) — по-прежнему peer-to-peer, не через sync API.

## Требования

- OpenKey Pro на каждом устройстве, которое должно синхронизироваться или клонироваться (или действительная аттестация **LAN Pro** на платформах без магазинного IAP — см. ниже)
- Одна **LAN** (не гостевой Wi‑Fi / изоляция клиентов)
- Для **merge-синхронизации**: оба устройства разблокированы с **Настройки → Устройства рядом**
- Для **клонирования сейфа** при настройке: существующее устройство разблокировано и рекламируется с сейфом; новое устройство на пути первого запуска **Устройство рядом**

Merge-синхронизация Nearby — **не** резервная копия. Держите также Pro [зашифрованный `.okbak`](./import-export#зашифрованное-резервное-копирование-pro). Клонирование копирует весь сейф один раз (включая вложения); после этого всё равно храните офлайн-бэкапы.

Маяки обнаружения включают **имя устройства открытым текстом** в LAN (и флаг `vault`, есть ли у пира уже аккаунт). Принимайте только свои устройства. Блокировка сейфа приостанавливает Nearby до следующей разблокировки.

Linux и Windows могут один раз запросить открытие LAN-портов (**UDP/TCP 47821**, **TCP 47822**). Разрешите эти запросы, чтобы пиры нашли эту машину.

## Скопировать сейф при настройке (клонирование сейфа)

Используйте, когда **новый телефон или десктоп** должен получить полную копию существующего сейфа по Wi‑Fi (без файла `.okbak`, без сервера).

1. На **существующем** устройстве: разблокируйте OpenKey → **Настройки → Устройства рядом** → включите **Видимость в локальной сети**. Пир должен показывать, что у него **есть сейф**.
2. На **новом** устройстве: выбор при первом запуске → **Устройство рядом** (или эквивалентный путь настройки).
3. Коснитесь обнаруженного пира → подтвердите копирование. Владелец сейфа отправляет (или пустое устройство забирает) зашифрованный сессией архив по LAN.
4. Разблокируйте на новом устройстве **тем же мастер-паролем**, что у источника. Пароль по проводу не передаётся — внутри спаренной сессии движутся только материал разблокировки и шифротекст сейфа.

Клонирование включает локальную БД, настройки, вложения, опциональный аватар и поля разблокировки аккаунта (email, salt, KDF, обёрнутый ключ сейфа). Если этот email уже есть на новом устройстве, клонирование завершается ошибкой `email_exists`.

**Клонирование vs Связать сейф**

| | Клонирование сейфа | Связать сейф |
|--|-------------|------------|
| Когда | Первый запуск / пустое устройство | У обоих устройств уже есть сейфы |
| Результат | Полная копия одного сейфа на пустое устройство | Общий отпечаток ключа сейфа; постоянная LWW merge-синхронизация |
| Мастер-пароль | Тот же пароль для разблокировки копии | Уже разблокировано с обеих сторон |

## Спарить устройства (merge-синхронизация)

1. Разблокируйте OpenKey на обоих устройствах → **Настройки → Устройства рядом**.
2. Включите **Видимость в локальной сети** (запоминается: возобновляется при следующей разблокировке, пока сейф разблокирован).
3. Коснитесь обнаруженного пира для спаривания (короткий код спаривания обменивается автоматически по LAN-сессии). Ручной ввод короткого кода всё ещё работает около двух минут, когда обнаружение неудобно.
4. После спаривания нажмите **Связать сейф**, чтобы оба разделяли один отпечаток ключа сейфа. Одно спаривание никогда не делится ключом сейфа автоматически.

Если ключи сейфа различаются, принимающее устройство может **принять** ключ пира (заменяет локальные данные сейфа после подтверждения мастер-пароля). Относитесь к связи + принятию как к полному доверию сейфу.

### Файрвол / обратное подключение

Некоторые десктопы (особенно macOS) блокируют входящий TCP. Сборки Linux и Windows могут один раз запросить **UDP/TCP 47821** и **TCP 47822**. Если пир не может дозвониться внутрь, OpenKey может попросить рекламирующий хост перезвонить гостю (только unicast UDP — код спаривания не транслируется в LAN). Разрешайте запросы локальной сети / файрвола, когда ОС спрашивает. Предпочитайте одну подсеть; VPN и private relay часто ломают обнаружение. Слишком много неверных кодов вызывает краткую блокировку.

## После связи

- Изменения синхронизируются автоматически, пока оба сейфа разблокированы и Nearby рекламируется.
- Используйте **Синхронизировать сейчас** для ручного обновления.
- Синхронизация — **last-write-wins по revision** (то же правило, что у [сервера](./server)) — по возможности редактируйте на одном устройстве за раз.
- **Доверенные устройства:** после успешного спаривания + связи сейфа пиры переподключаются и синхронизируются, когда Nearby включён — без повторного спаривания.
- **Только доверенные сети (опционально):** добавьте SSID дома/офиса; Nearby приостанавливается, если текущий SSID не в списке (и блокирует запуск, если список пуст). Когда ОС не может прочитать SSID, Nearby может работать с предупреждающим баннером.
- **Отвязать** отзывает LAN-доверие, останавливает синхронизацию и очищает LAN Pro claims этого пира.

## Отправить запись

Можно отправить один логин спаренному пиру без ожидания полной синхронизации сейфа:

1. Откройте запись (или используйте действия пира Nearby в **Настройки → Устройства рядом**).
2. Выберите **Отправить на устройство** / отправить запись этому пиру.
3. Пир получает шифротекст по LAN-сессии и может сохранить локально.

Используйте для разовых обменов в LAN; предпочитайте [организации и шаринг](./sharing), когда пиры используют один self-hosted сервер.

## Аттестация LAN Pro {#lan-pro-attestation}

На платформах **без** покупки в магазине (обычно Windows / Linux) Pro-пир со **связанным сейфом** может передать статус **LAN Pro**, чтобы другое устройство сняло лимиты Pro через Nearby. Одного спаривания недостаточно — сначала нажмите **Связать сейф**.

- Только удобство — **не** криптодоказательство покупки.
- Android, iOS и macOS (магазинный IAP) **игнорируют** LAN Pro; купите или восстановите Pro в том магазине.
- Отвязка останавливает аттестацию.

## Сводка доверия

| Действие | Смысл доверия |
|--------|-------------------|
| Спарить | Ключ сессии с этим пиром в LAN |
| Клонирование сейфа | Пир получает полную копию сейфа (шифротекст + материал разблокировки); нужен тот же мастер-пароль для разблокировки |
| Связать сейф | Поделиться материалом ключа сейфа — пир может синхронизировать полный шифротекст сейфа |
| Отправить запись | Пир получает шифротекст этой записи |
| LAN Pro | Пир может снять лимиты Pro на платформах без IAP |

Спаривайте, клонируйте и связывайте только с устройствами и людьми, которым доверяете. Подробнее: [Безопасность → Модель угроз](./security#модель-угроз).
