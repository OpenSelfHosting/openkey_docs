# 自动填充密码：如何设置与修复

**自动填充** 是那个把密码管理器从「密码存放地」变成你真正会用的工具的功能。你不必打开保险库、找到对应条目、复制一串字符，只需聚焦到用户名字段，建议就会出现。

这是大多数人第一次搜索的地方 —「how to autofill」「autofill password」「autofill chrome」「autofill iphone」— 也是大多数人第一次放弃的地方。所以：它是什么、如何在各处开启，以及如何让它变得可靠。

## 自动填充实际做了什么

三种不同的机制共用同一个名字：

1. **表单自动填充** — 检测到登录页面，管理器给出匹配的条目，你点一下，用户名和密码就被填好。
2. **保存提示** — 你登录之后，管理器会询问是否存储或更新这些凭据。
3. **密码生成** — 在注册表单上，管理器可以在你输入的同时创建一个强密码并写入字段。

第三项才是被低估的部分。*在* 注册 *过程中* 生成密码，是可得的最佳习惯改变：它消除了那个你本来会编一个弱密码的瞬间，因为在你能覆盖输入之前字段已经被填好了。

## 在 Chrome 中开启自动填充

Chrome 内置管理器和第三方管理器位于同一个地方，这就是这件事令人困惑的原因。

1. 打开 `chrome://settings/addresses`（密码和自动填充）。
2. 打开 **提供保存密码**。
3. 如果你想要一键登录，打开 **自动使用已保存的密码登录**。
4. 在 **密码、passkeys 和自动填充** 下，选择你想使用的管理器 — Chrome 内置的，或你的密码管理器扩展。
5. 如果你使用扩展，打开一次它的弹窗，确认它已解锁。

键盘优先的填充通常也能用：Windows 和 Linux 上是 `Ctrl+Shift+L`，macOS 上是 `⌘⇧L`。如果这个快捷键已被另一个扩展占用，可在浏览器的扩展键盘快捷键设置中重新映射。

## Firefox 中的自动填充

Firefox 有自己的内置管理器，并且对哪些扩展可以执行填充更为严格。如果建议没有出现，请检查该扩展在该网站上是否被允许，以及扩展是否已解锁。Firefox 会自动使用 `openkey@openselfhosting.local` 作为原生消息主机 — 在该平台上无需手动编辑清单。

## iPhone 和 iPad 上的自动填充

iOS 不像 Android 那样有全局的「从任意应用填充」开关。你要按应用使用 **AutoFill Passwords** 流程：

1. 安装你的密码管理器，并在系统设置中将其启为 AutoFill 提供方。
2. 在你正要登录的应用中，点击用户名或密码字段，并从字段菜单（或键盘的密码行）中选择你的提供方。
3. 出现提示时，用 Face ID / Touch ID 确认。

有两个值得了解的 iOS 习惯：如果 OpenKey 没有出现在提供方列表中，说明它没有在系统设置里启用；而且在更换提供方后，iOS 有时需要重启目标应用。[Passkeys](/zh/blog/what-are-passkeys) 也走同一个 AutoFill 选择器，因此同一套设置对两者都适用。

## Android 上的自动填充

Android 提供了真正系统级的密码与 passkey 提供方，这让它成为移动平台上最顺手的那个：

1. 打开 **设置 → 安全 → 自动填充服务**，选择你的管理器。
2. 授予权限提示。
3. 在管理器的设置中，选择 **内联建议** 或 **弹窗**，并可选择要求每次填充前都进行生物识别。
4. 在一个你已有凭据的网站上用测试登录确认。

要求填充前进行生物识别是一项有实质意义的升级：它堵上了「有人走到你已解锁的手机前、读取你收件箱里那些密码」这个漏洞，同时又不会让自动填充变得烦人。

## 桌面应用上的自动填充

桌面自动填充是一次双向握手。启用应用的自动填充设置后，应用会注册一个 **原生消息主机**，随后浏览器扩展通过本地套接字与已解锁的应用通信。在 macOS 上，主机脚本需要在你的 `PATH` 中有 Python 3；在 Linux 和 Windows 上，切换该设置时应用会为你写入清单文件。

如果扩展连不上应用，几乎总是这个握手出了问题 — 完整清单请看[自动填充不工作](/zh/blog/autofill-not-working)。

## 设置 OpenKey 自动填充

| 平台 | 步骤 |
|----------|-------|
| Android | **设置 → 安全** → 将 OpenKey 启用为系统提供方 → 解锁保险库 |
| iOS / macOS | 在系统 AutoFill 设置中启用 OpenKey → 授予系统提示权限 → 重启目标应用 |
| Windows / Linux | **设置 → 安全** → 启用自动填充以注册原生主机 |
| 浏览器 | 构建并加载 `openkey_extension` → 设置服务器 URL，或选择 **使用桌面应用** |

有两种解锁模式可用。**独立模式** 用你的邮箱和主密码，针对你的自托管服务器解锁扩展。**桌面桥接** 通过已解锁的应用来填充，无需单独解锁扩展 — 通常是更好的日常体验，因为应用是你唯一的解锁入口。

完整流程：[浏览器扩展指南](/zh/guide/extension)。

## 自动填充同样是一项安全功能

自动填充不只是便利；它是一项控制手段。

- **抗钓鱼。** 会把登录项与它被保存时的确切来源匹配的管理器，在仿冒域名上不会给出任何建议。手动把密码粘贴进一个做得极其逼真的银行页面副本，正是自动填充所阻止的攻击。
- **更少的明文副本。** 没有密码管理器应用里的副本，没有剪贴板历史记录，没有躺在笔记文件里的密码。
- **自然的轮换。** 当某个网站要求设置新密码时，内联生成一个就让唯一密码成为阻力最小的路径。

## 自动填充与 passkeys

Passkeys 彻底去掉了密码框位，于是没有任何东西需要填充 — 凭据是从保险库中取出并当场签名的。你用于自动填充的那次解锁同样覆盖 WebAuthn，这正是提供方只需设置一次就能兼顾两件事的原因。[什么是 passkeys？](/zh/blog/what-are-passkeys)

## 如果自动填充不工作

十有八九的情况是五件事之一：保险库处于锁定状态、系统设置里选错了提供方、扩展没有连接到应用、更换提供方后浏览器需要重启，或自动填充被有意限制在某一个浏览器上。按顺序走一遍[自动填充不工作](/zh/blog/autofill-not-working)里的分步版本。
