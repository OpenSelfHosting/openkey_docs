# LastPass 替代品：如何迁移，以及该找什么

在世界上的大部分地区，LastPass 都是最广为人知的密码管理器品牌名，这让「lastpass alternative」成为这个品类中搜索量最高的比较词之一。人们出于三种不同的原因搜到它，而他们需要的也是三样不同的东西：

1. **信任** — 你想换一个答案来回答「谁能读取我的密码」。
2. **成本或限额** — 免费层级或家庭套餐不再合适。
3. **功能** — 你想要 passkeys、自托管或开发者密钥。

本文讲的是迁移过程中究竟会改变什么、在你做出决定之前该核查什么，以及如何完成这次切换，而中间不出现一个「什么都登不进去」的窗口。

## 让这次迁移与众不同的原因

LastPass 已经在新闻里待了很久，而它对迁移造成的实际影响是实务性的，而不是戏剧性的：

- **导出结果是 CSV。** 明文、未加密，每个密码都清清楚楚地摆着。任何人拿到那个文件，就等于拿到了你的保险库。
- **可能提供受密码保护的导出。** 如果你的套餐有这一项，它比默认的 CSV 安全得多。请用它。
- **导出对附件的支持有限。** 附在条目上的文件通常不会随 CSV 一起被带出来。
- **对长期用户来说保险库很大。** 一个用了十年的账户可能在许多文件夹里装着数百个条目。预留出一个下午吧。

这次迁移中唯一最重要的一点是：它是 **一次单向导出，加一次一次性导入**。谨慎操作、逐一验证，然后才去删除旧账户。

## 替代品的四项要求

### 1. 它必须是可证明的零知识

查清谁持有解密密钥。如果某个客服人员能重置你的主密码或解锁你的保险库，那无论营销文案怎么写，你都是把明文交给了他们的基础设施。好的替代品会在你创建保险库 *之前* 就告诉你：被遗忘的主密码任何人都无法恢复 — 包括他们自己。

### 2. 它必须能导入你的 LastPass CSV

确认导入器明确支持 LastPass CSV，并确认文件夹结构会映射到集合。如果工具允许，先用一份部分导出做测试。

### 3. 它不能把退出变成付费墙

要留意的是这种不对称：**导入免费，导出收费**。让你进来、却要收费才能离开的管理器，实际上悄悄地把你的数据变成了你留下的理由。在迁移之前查清导出属于哪个层级，而不是之后。

### 4. 它必须能在你的设备上正常自动填充

第一周里你最在意的肯定是自动填充。在删除旧账户之前，先在你最常用的三个网站上测试它。

## 逐步迁移

### 1. 从 LastPass 导出

1. 登录，打开 **设置 → 高级导出**，选择 **LastPass CSV**（如果你的套餐提供受密码保护的导出，就选那个）。
2. 把它保存到你自己掌控的位置，而不是共享的云文件夹。
3. 不要用邮件发送它，也不要把它留在「下载」文件夹里。

### 2. 导入新的管理器

在 OpenKey 中：**设置 → 数据 → 导入与导出 → 导入 → LastPass CSV**，选择文件并确认。全过程都在本地完成 — 没有服务器往返，你的明文也绝不会触及同步服务器。

预期会有文件夹到集合的映射；对于非常老的保险库，还可能有一些条目落下来时没有对应文件夹。之后逐条检查，而不要想当然。

### 3. 在你开始改密码 *之前* 打开自动填充

这个顺序很重要。自动填充一旦正常工作，从此以后你做的每一次登录都会被自动捕获，保险库会在你工作的同时自我整理。

- [自动填充密码](/zh/blog/autofill-passwords) — 设置指南
- [自动填充不工作](/zh/blog/autofill-not-working) — 它不配合时怎么办

### 4. 先修价值最高的账户

不要试图一次轮换 400 个密码。先轮换邮箱、银行和云端，每换一个就当场生成一个：

```bash
openkey gen -l 24
```

同时加上 2FA（[指南](/zh/blog/two-factor-authentication)），并在网站提供 passkey 的地方加上一个（[什么是 passkeys？](/zh/blog/what-are-passkeys)）。

### 5. 验证，然后销毁导出文件

- 抽查重要登录项；如果用过 TOTP，也包括 TOTP 条目。
- 确认自动填充在你主力浏览器和手机上都能用。
- 确认你能在第二台设备上登录。
- **安全地删除那个 CSV。** 要真正做到位；在 SSD 上「已删除」的文件仍可能是可恢复的。覆写文件并清空回收站，是一个合理的最低要求。
- 那个明文文件里待过很久的凭据，都要轮换掉。

### 6. 取消订阅前先留一份备份

先做一份加密的本地备份 — 在 OpenKey 中是 `.okbak`，或你所用的管理器的同等物。然后再删除旧账户。取消订阅应当是最后一步，而不是第二步。

## 人们通常会换到哪里

| 想要…… | 看看 |
|-------------|---------|
| 不要服务器、不要厂商，只要本地文件 | 像 KeePass 这样的文件型管理器 — 很好，但备份由你自己负责 |
| 自己的同步服务器，代码开放 | 一个可自托管的管理器 — [OpenKey](/zh/blog/self-hosted-password-manager) 就是 |
| 厂商级打磨，且有真正可用的免费层级 | 任意一家主流管理器，按[这里的评分标准](/zh/blog/best-password-managers)来判断 |
| 根本不迁移 — 只是再加一个管理器 | 两个并行用一个月；在你有把握之前，把旧账户设为只读 |

并行运行两个管理器是风险最低的选项，而且不花一分钱。把旧的那个的自动填充关掉，应用留着别删，等过了一周毫无摩擦的登录之后，再删除那个账户。

## 搜索数据说明

Google Trends（全球范围，过去 12 个月）显示，LastPass 替代品是一个真实且不断增长的查询簇，而 1Password 替代品吸引到的搜索兴趣比 LastPass 替代品更多。把这些「替代品」查询互相比较：

| 查询 | 簇内相对关注度 |
|-------|-------------------------------|
| 1password alternative | 100 |
| lastpass alternative | 26 |
| proton pass alternative | 7 |
| dashlane alternative | 1 |

「1password alternative」的关注度约为「lastpass alternative」的四倍，这一点值得停下来想一想：它说明这个品类中最大的一波迁移潮 *不是* 在离开 LastPass，而是被 1Password 的定价与家庭套餐结构推动的。搜索「1password pricing」同样是与 Bitwarden 相关的上升最快查询之一，同比增长约 200%。

头部词条仍然压倒性地以品牌为锚。在「password manager」的细化词中，Bitwarden 和 1Password 吸引到的品牌搜索都比 LastPass 多，而 LastPass 更多出现在 *定义类* 和恢复类查询里 — 最显眼的是「lastpass forgot master password」，它是「forgot master password」之下最强的单个相关查询。

这种分裂才是有用的洞察：出了事的时候人们搜 LastPass，变贵的时候人们搜 1Password。不同的问题，不同的解法 — 而其中一个根本不是安全问题。

Method: Google Trends，全球范围，过去 12 个月，2026 年九月提取。数字为归一化的相对关注度（0–100），而非搜索量。

## 一分钟版本

从 LastPass 导出（如果提供受密码保护的导出，就用它），把 CSV 导入一个导出免费且保险库为零知识的替代品，在改动任何东西之前先打开自动填充，先轮换邮箱和银行，然后删除导出文件，最后才删除旧账户。取消订阅前保留一份加密备份。
