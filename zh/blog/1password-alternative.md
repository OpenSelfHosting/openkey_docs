# 1Password 替代品：换掉它而不丢你的保险库

1Password 是一款优秀的产品，而它之所以优秀的原因之一，恰恰是它没有免费层级。这一项单独的设计决定，是人们搜索「1password alternative」最常见的原因 — 这是整个品类中搜索量最高的替代品查询，关注度约为「lastpass alternative」的四倍。

本文是写给理由属于以下三类之一的读者：**成本**、**家庭共享上的摩擦**，或**想把同步放在自己的硬件上**。这不是一场控诉；1Password 是一个合理的选择，而诚实的说法是：「如果你没有这个问题，那就留下。」

## 换掉的三个真实理由

### 成本

订阅费是入场券，而且没有永久免费的选项。价格会按商店和地区本地化，所以诚实的说法是结构性的：你是在拿一份订阅费，去和「别处的免费层级」或「一次性购买 + 你自己的服务器」作比较。

查询数据也印证了这一点。「1password pricing」是与 Bitwarden 相关的上升最快细化词之一，同比增长约 **200%**，而在好几个主要品牌之下，与价格相关的词都主导了上升榜。

### 家庭与团队共享

家庭套餐是摩擦的常见来源 — 席位管理、某个孩子后来需要独立账户时的套餐升级，以及设备各不相同的多户之间共享。如果你的家里混用 iOS/Android/Windows，或者你想和一个没有家庭套餐的人共享，这就是一个正当的迁移理由。

### 自托管

1Password 早在前些时候就停用了独立的本地保险库，因此同步要经过厂商。如果你的要求是加密数据必须放在你掌控的基础设施上，那这是硬性要求而不是偏好 — 而它指向的是一款可自托管的管理器。

## 迁移之前：成本真的是问题所在吗？

这值得诚实地查一遍，因为迁移是一个下午的工作量，而如果你不小心，你会做不止一次：

- **你真的需要搬走吗？** 一年的订阅费往往比迁移花掉的时间更便宜。如果痛点只是每年那一次扣款，答案可能就是留下。
- **问题出在套餐还是席位数？** 个人套餐和家庭套餐是不同的产品；因为家庭套餐别扭而搬走，与因为想要一份订阅都没有而搬走，是两个不同的决定。
- **你真的需要一个站得住脚的理由来自托管吗？** 如果你家里没人能运行一台服务器，自托管就是一个你很快会放弃的爱好。Nearby 局域网同步能覆盖其中大部分收益，却完全不需要那份维护。

如果答案是「是」，那就搬 — 而本文余下部分讲的就是怎么做。

## 逐步迁移

### 1. 从 1Password 导出

1. 在网页或桌面应用上登录。
2. 打开 **设置 → 导出**，选择 **1Password CSV**。
3. 如果可以拿到，优先选择**加密的 1PUX** 导出 — 它会用密码把条目锁住，而不是写出明文。
4. 把它保存到你掌控的某个地方，然后挪到离线环境。

复杂的条目类型 — 带附件的安全笔记、身份信息、文档、Wi-Fi 凭据 — 导出时都会摊平成类似登录项的行。重要的那些要预备好手工重建。

### 2. 导入新的管理器

在 OpenKey 中：**设置 → 数据 → 导入与导出 → 导入 → 1Password CSV**。导入在本地完成，不会上传任何东西。能干净映射的文件夹会变成集合。

### 3. 立刻打开自动填充

自动填充正常工作之后，你从此登录的每个站点都会替你保存下来，于是保险库会在你轮换密码的同时自我修复。

- [自动填充密码](/zh/blog/autofill-passwords)
- [自动填充不工作](/zh/blog/autofill-not-working) — 如果没有候选项

### 4. 轮换真正要紧的账户

先换邮箱，然后是银行和云端，剩下的随着各个站点的提示一个个来。在本地生成每个密码：

```bash
openkey gen -l 24 -c
```

在你打开安全设置时顺手加上 2FA（[指南](/zh/blog/two-factor-authentication)），并在提供 passkey 的地方加上一个（[什么是 passkeys？](/zh/blog/what-are-passkeys)）。

### 5. 手工重建那些共享条目

这是人们最容易低估的部分。需要重建的有：

- **支付卡片**，按发卡方分组
- 用于填表的 **身份信息**
- 你存过的 **Wi-Fi 与设备凭据**
- 带附件的 **安全笔记** — 那些没有跟过来

OpenKey 把卡片、加密钱包和开发者密钥当作保险库里的一等区域，而不是自由文本笔记，这让这次重建比在只有笔记的管理器里轻松得多。参见[使用应用](/zh/guide/app)。

### 6. 先做备份，然后取消

在取消 **之前** 导出一份加密的本地备份（OpenKey 中是 `.okbak`），然后在第二台设备上验证一次全新登录。只有到这一步才去关闭旧账户。

### 7. 销毁导出文件

加密的导出：直接删除。明文 CSV：覆写，然后彻底擦除。凡是在明文文件里待过一周的东西，无论如何都该轮换掉。

## 在替代品中该找什么

| 要求 | 该验证什么 |
|-------------|----------------|
| 不贵 | 一个涵盖保险库、自动填充和同步的免费层级 — 并且明确写出 *条目* 上限 |
| 家庭共享 | 带撤销功能的共享集合，以及孩子是否需要单独的套餐 |
| 1Password CSV 导入 | 明确支持，并且有文件夹映射 |
| 免费导出 | 确认所属层级；导出的付费墙会让数据沦为人质 |
| 自托管 | 可选，但它会彻底改变信任模型 |
| passkeys 与 TOTP | 两者都要，能用，而不是「即将推出」 |
| CLI 或 API | 只要你有任何脚本化需求，它就很有价值 |

完整标准和一张评分表见：[最佳密码管理器](/zh/blog/best-password-managers)。

## 家庭与团队这一层

如果驱动因素是共享而不是成本，那么在挑选个人版套餐之前先看看这些：

- [家庭密码管理器](/zh/blog/password-manager-for-family) — 家庭配置、孩子、共享账户
- [团队密码管理器](/zh/blog/password-manager-for-teams) — 组织、角色、撤销、离职处理

在 OpenKey 中，组织和共享集合需要 Pro 加上一台自托管服务器，而它们存储的一切 — 组织名称、条目载荷、附件 — 始终保持密文。客户端为接收方包装密钥；服务器从不解包。在围绕这一点设计流程之前，有个细节值得知道：**条目共享是快照**，不是实时文档。撤销一次共享会阻止待处理的接受，但不会删除接收方已经接受的副本。若需要持续共享访问，请改用组织共享集合。

## 搜索数据说明

Google Trends（全球范围，过去 12 个月）让这次迁移的形状变得明明白白。把这些替代品查询互相比较：

| 查询 | 簇内相对关注度 |
|-------|-------------------------------|
| **1password alternative** | **100** |
| lastpass alternative | 26 |
| proton pass alternative | 7 |
| dashlane alternative | 1 |

而挂在主要品牌下面的那些上升查询，主导它们的是商业问题而不是安全问题：就 Bitwarden 而言，「bitwarden price increase」以约 **+450%** 领跑，「bitwarden review」和「bitwarden lite」都在 +350% 左右，「bitwarden pricing」在 +190% 左右。开源、可自托管和小团队的兴趣同样在攀升 — 「bitwarden open source」、「bitwarden enterprise」和「bitwarden cli」都出现在上升榜上。

两个结论。第一，这个品类中驱动人们换掉的主要因素是 **价格**，而不是泄露焦虑。第二，上升最快的相邻兴趣是开源、企业版和 CLI — 这说明那些离开付费套餐的人，是在找一个自己能运行、能亲自检查的东西。

## 一分钟版本

如果痛点是成本，一份 1Password CSV 导出加上一个导出同样免费的管理器，就能不花一分钱地脱身。如果痛点是家庭共享或自托管，就先按这两项要求来选，价格排第二。导出、在本地导入、打开自动填充、轮换邮箱和银行、手工重建卡片与笔记、做一份加密备份，然后取消订阅。
